一、赛道本质：这个题在考什么

主题七出自上海市排水管理体制改革（2025 年 4 月市政府印发方案）：到 2026 年底，石洞口、竹园、白龙港三大片区（污水处理规模 744 万 m³/d，占全市约 70%）实现"厂站网一体化"运维管理，要求"统一运行调度"，并建设"排水感知体系及模拟评估系统"。

改革直面的问题：厂站网分离、运行效率不高；雨天泵站放江污染突出、污水厂进水浓度偏低。因此赛题要的不是"再造一个污水厂工艺"，而是给厂里装上"预见性"——提前知道来水，才能提前调整工艺、提前调度泵站。

答辩可用一句话：我们做的正是"感知体系"里最前端的一段——把上游管网与泵站信号变成厂前进水的超前认知。

核心物理洞察：输送延迟 = 天然的超前量

一句话：污水要走 0.3~3.6 小时——上游信号是厂前进水的"预告片"。所以"超前感知"不是模型魔法，而是把物理事实工程化：上游信号 + 降雨 → 1~3h 后厂前进水（水量 + 水质负荷）→ 四级预警 → 泵站协同建议。

二、数据困局与破局（本项目最核心的方法论）

困局：组委会只给 Date1 静态骨架（26 座泵站配泵能力 / 服务范围，合计约 40.5 m³/s）；泰和没有任何时序运行数据；国内管网 / 厂 SCADA 无公开渠道。

破局（三层数据战略）：

  1. 方法有效性 → 国际公开真实数据集：Köln-Weiden（一张表内含上游管网液位×3 + 调蓄液位 + 降雨 + 厂前进水，3 年 15min 连续，105,120 步）——结构与赛题完全同构，证明"上游液位+降雨 → 厂前进水"预测方法在真实厂网数据上有效；另用丹麦 DHI 污水厂做两座真实厂互为源/目标的零标签迁移验证。
  2. 场景完整性 → 官方骨架 + 自研模拟器：按 Date1 概化 43 节点 / 42 管段 / 6 泵站树状管网，五机制生成全要素时序，把"感知-预测-预警-预控"闭环在物理一致场景中打通（明确标注模拟）。
  3. 驱动真实性 → 官方实测降雨：上海市水务局「水情信息」（data.sh.gov.cn，无条件开放）52 站 10min 级实测（1150 万行原始 → 24.9 万行栅格），以 2024 汛期 92 天真实降雨驱动场景（雨时占比 20.9%）。
结论 / 实验用什么数据性质

四、七步详解（做法 → 为什么 → 数字）

管网模拟器：五机制生成泰和全要素时序

旱天双峰基流（早 9 晚 20 双峰，周末 ×0.92）· 雨天入流入渗 RDII（Q = 10·ψ·i·A/k，ψ=0.35）· 输送延迟（τ = L/0.8m/s，零填充因果路由）· 泵站启停（按负荷比例投泵）· 水质两源混合 + 初期冲刷 + 冲击事件（日概率 5%，COD ×1.8~4.0）。

五机制参数逐项标注"规范取值（GB 50014）/ 文献典型值（BSM2 同量级）/ 经验设定"；用统计生成器而非直接 SWMM，是为了快、可控、可标注事件；SWMM 留给调度验证做物理模型在环。因果性是底线：_delay() 零填充不回绕 + 单元测试防回归。

源码：src/simulation/timeseries.py · 参数表：docs/数据说明.md · 图：结果全景 · 数据组

特征工程：62 维，只用发布时刻及之前的信息

对目标量与每个输入量统一构造：滞后 {1,2,3,4,6,8,12,24} 步 + 一阶差分 + 6 步滚动均值；再加小时（含分钟小数）与星期。泰和 5min 步长下共 62 维。

滞后集覆盖 5min~2h 多时间尺度；"发布时刻语义"= t 时刻只用 ≤t 的观测，目标是 t+h 的真值——所有模型与基线共用同一对齐，指标可横向比较。

源码：src/models/forecast.py::feature_rows

防泄漏切分：时间顺序 + 提前量隔离（含一个真实修复故事）

按时间 75%/25% 切分；训练段末端再剔除 h 步——否则最后几条训练样本的标签会落进测试段，等于偷看未来。

早期版本用 np.roll 前移上游序列、厂前瞬时响应降雨，导致"提前量越长精度反而越高"的伪现象；发现后改为零填充因果延迟，并加因果性单元测试。知道泄漏长什么样、怎么发现、怎么修复、怎么防回归——这是方法可信度的直接证据。

源码：src/serving/model.py::training_split · 测试：tests/test_simulation.py

模型与基线：LightGBM 主模型 + 四类对照

LightGBM（400 棵 / lr 0.05 / 63 叶）；对照：persistence（当前值）、季节朴素（昨日同刻）、MLP(64-32)、LSTM（2 层×64、3h 窗口、5.2 万参数）。

表格滞后特征 + 非线性阈值（泵启停）是树的强项；训练秒级（Köln +1h：3.3s vs LSTM 45.8s）；原生支持缺测（NaN 走单独分支）是容错基础；TreeSHAP 可精确分解。选型理由是"同精度档位下更便宜、更稳、可解释"。

数字：Köln 0.943/0.807/0.676 vs LSTM 0.922/0.787/0.637；泰和 0.983/0.972/0.956

概率预测：P10–P90 分位数（诚实标注"未校准"）

LightGBM 分位数回归（α=0.1/0.9，各 300 棵）输出区间；用 PICP（覆盖率）与 MPIW（区间宽度）评估。

Köln 覆盖率 71.5% / 72.1% / 73.8%，低于名义 80%——区间偏窄、未校准。如实标注、不作保守上界；上线前留出校准集做分位数校准，暴雨场景单独检验覆盖率。"给一个假保守的区间比诚实标注更危险。"

数字：reports/forecast_metrics.json · 图：fig10

压力测试与跨厂迁移：暴露失败 → 修复 → 诚实标注

设计暴雨（P=5/50/100a，上海暴雨强度公式 + 芝加哥雨型）与台风"烟花"实测回放；两座真实厂（Köln ↔ 丹麦）互为源/目标做零标签迁移。

P100 未见暴雨基准 NSE 0.149、峰值低估 −85%（暴露）→ 加入 P5/P50 暴雨增广后 P100 NSE 0.954（修复；但 P5/P50 已入训、不再独立——标注）。迁移：+2h 直迁 0.511/0.708，低于本地训练 0.677/0.837 → 新厂上线必须先用本厂数据评估/重训。

数字：reports/stress_test.json、reports/real_transfer.json · 图：fig13 / fig21 / fig26

闭环与服务化：预警 → 调度 → 容错 → 监控 → 谱系

四级预警（60/80/95/110% × 设计能力）驱动"雨前预抽空 → 错峰开泵 → 限流+调蓄"；SWMM 在环四策略对比；FastAPI 服务（严格 + 容错双模式）；质量控制 + 漂移监控回退；183 项谱系 SHA-256 核验。

SWMM 揭示"削峰-冒溢权衡前沿"：稳健版削 28%（冒溢不增）/ 激进版削 89%（冒溢 +6.2%）。容错链路的量化价值：全部液位计离线时 0.773 vs 常规补齐 0.708，而严格模式直接拒绝（可服务率 0）。

数字：reports/swmm_control.json、reports/robustness.json · 源码：src/control/、src/serving/

五、三条边界与展望（必须主动说）

边界 1 · 模拟非实测

泰和是模拟场景（官方只给静态骨架）；真实性能证据只有 Köln 等公开实测。所有泰和数字不代表实厂性能。

边界 2 · 区间未校准

P10–P90 覆盖率 67%~74%（名义 80%）；P90 不能当保守上界，需校准后才能用于生产阈值。

边界 3 · 未实厂率定

预警阈值 / SWMM 参数 / 效益数值均为概化设定与模拟推算；橙/红无真实正例，上线前需旁路验证。

展望（下一步四条）

  1. 申请上海政务平台"有条件开放"的泵站运行 / 排水系统数据，做实厂旁路验证；
  2. P10–P90 区间校准与暴雨覆盖率专项；
  3. 接入降雨数值预报作为外生输入 + 在线学习；
  4. 规则调控升级为基于模型预测控制（MPC）的泵群优化调度。
