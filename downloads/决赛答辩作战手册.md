## 〇、30 秒总览（答辩当天开场前先看这页）

**一句话项目**：我们为"厂站网一体化"构建了一套"感知→预测→预警→预控"闭环——融合上游管网液位、泵站状态与降雨，超前 1~3 小时预测污水厂进水水量与水质负荷，并给出四级预警与泵站协同调度建议；方法在德国科隆（Köln-Weiden）真实厂网数据上验证，在泰和场景（官方泵站骨架 + 上海实测降雨）完成全链路模拟打通。

**三个必须会背的数字**（细节见第四章）：

1. Köln 真实数据 +1h/+2h/+3h 进水预测 NSE = **0.943 / 0.807 / 0.676**（当前值基线 0.839 / 0.623 / 0.423，全提前量超过基线）。
2. 泰和场景 +1h/+2h/+3h NSE = **0.983 / 0.972 / 0.956**，MAPE ≤ 2.5%（模拟场景，明确标注）。
3. 全链路可复现：`bash deliverables/run_all.sh` 一键复现；谱系清单 **183 个文件** SHA-256 逐项可核验（`python -m src.viz.lineage --verify`）；22 个单元测试全绿（CI 在 GitHub Actions 上每次 push 自动跑）。

**三个必须主动承认的边界**（评委问"局限/可信度"时直接用）：

1. 泰和时序为**模拟**（组委会只给 Date1 静态骨架），所有泰和数字**不代表实厂性能**；真实性能证据一律以 Köln 等公开实测为准。
2. P10–P90 区间**未经校准**（覆盖率 67~74%，低于名义 80%），不能当保守上界用，上线前需单独校准。
3. 预警 / SWMM 调度 / 效益数值均为**模拟场景推算**，橙/红等级没有真实正例；上线前需实厂旁路验证。

**五条答辩纪律**：

1. **诚实优先**：评委是行业行家（上海城投、同济、哈工大背景专家），夸大必被追问戳穿；"边界说得越清楚，可信度越高"是本项目既定策略（`docs/路演专家问答.md` 全文基调）。
2. **每个数字都能指到出处**：被追问"这数哪来的"→ 直接说 `reports/forecast_metrics.json` / `docs/实验结果.md`（自动生成，不手改）。
3. **先结论后展开**：先一句话回答，再补 2~3 句证据；不绕。
4. **区分"真实/模拟"**：开口先给数据性质（真实验证 or 模拟场景），这是最容易建立信任的细节。
5. **不会的题**："这一点我们还没做，我的判断是……"——承认边界 + 给思路，远好过硬编。

## 二、底层逻辑：一个故事讲清整个项目

### 2.1 核心物理洞察（一切设计的出发点）

污水从上游管网流到厂前**需要时间**：泰和系统概化设计流速 0.8 m/s、节点距厂 0.8~10.5 km，输送延迟 τ = L/v ≈ **0.3~3.6 小时**。

⇒ 上游节点**此刻**的液位、流量、泵站状态，就是厂前 **0.3~3.6 小时后**的"预演"。**"超前感知"的物理基础就是这个输送延迟**——不是模型魔法，是"水还没到、信号先到"。

⇒ 我们做的事：把"上游信号 + 降雨"映射到"厂前进水（1~3h 后）"，再映射到"预警等级 + 泵站调度建议"。

> 如果评委只记住一句话，让他记住这句：**"污水从管网到厂前要走 0.3~3.6 小时——我们在水到之前，就把它的量和水质算出来了。"**

### 2.2 数据困局与破局（我们的方法论，评分表"数据处理 15 分"的主战场）

**困局**：组委会只给 Date1 静态骨架（26 座泵站配泵能力/服务范围，合计约 40.5 m³/s）；**泰和没有任何时序运行数据**；国内管网/厂 SCADA 无公开渠道。

**破局（三层数据战略）**：

1. **方法有效性 → 国际公开真实数据集**：Köln-Weiden（Zenodo 6992694，CC-BY）一张表内含上游管网液位×3 + 调蓄液位 + 降雨 + 厂前进水流量，3 年 15min 连续（105,120 步）——结构与赛题完全同构，用于证明"上游液位+降雨 → 厂前进水"预测方法在真实厂网数据上有效（NSE 0.943/0.807/0.676）。另用丹麦 DHI 污水厂（Zenodo 15301164）做**两座真实厂互为源/目标的零标签迁移验证**（诚实结论：有效，但不及本地训练）。
2. **场景可用性 → 官方骨架 + 自研模拟器**：按 Date1 概化 43 节点/42 管段/6 泵站树状管网，五个物理机制生成全要素时序（节点液位/流量、泵站运行、厂前水量水质、冲击事件），把"感知-预测-预警-预控"闭环在物理一致的场景里全链路打通（NSE 0.983/0.972/0.956，明确标注模拟）。
3. **驱动数据真实性 → 官方实测降雨**：降雨不用模拟——上海市水务局「水情信息」（data.sh.gov.cn，无条件开放）52 站 10min 级实测（1150 万行原始 → 24.9 万行栅格），以 **2024 汛期 92 天真实降雨**驱动模拟场景（雨时占比 20.9%，覆盖梅雨连阴与台风强降雨）。

## 三、系统七段详解（问题 → 做法 → 为什么 → 数字 → 追问）

### 3.1 数据体系

**做法**：真实/模拟两类数据全部登记（`data/DATA_CATALOG.md`，15 类数据集逐项标来源与许可）。

- 真实：Date1 官方骨架；上海水情（官方无条件开放，2021-01~2025-09）；Köln（CC-BY-4.0）；丹麦 DHI（CC-BY-NC-4.0，仅非商业）；NOAA/ERA5 气象、CNEMC 断面水质等。
- 模拟：泰和全部时序（`src/simulation/`，seed 固定可复现）。参数来源逐项标注：规范取值（GB 50014-2021 径流系数 0.35、流速 0.8 m/s）/ 文献典型值（BSM2 同量级进水浓度）/ 经验设定（冲击事件概率等）——见 `docs/数据说明.md` 的五机制表。
- 报告 §2.3 有一张"哪个结论用什么数据"的对应表——**这是最该主动展示的表**。

**追问准备**：

- "为什么不用国内数据？"→ 组委会未提供时序；国内管网/厂 SCADA 无公开渠道（我们的渠道矩阵调研见 `docs/管网数据调研分析报告.md`）；合规优先，只用官方开放与开放许可数据。
- "你们有没有拿到国内厂的数据？"→ 如实说：有一条人脉线索经核实属于另一座厂、与泰和无关，且无法作为本作品证据，**未采用**（宁可不用，也不混入来源不清的数据）。
- "数据许可都核实了吗？"→ 已逐项登记；丹麦数据仅非商业、赛后可依规使用；提交前团队再复核一遍条款（`docs/路演专家问答.md` Q14）。

### 3.2 管网模拟器（技术深度核心之一）

**做法**：五个物理机制（`src/simulation/timeseries.py`，参数 `config.py`）：

| 机制 | 公式（即代码实现） | 性质 |
|---|---|---|
| ① 旱天基流 | Q₀·f(h)·w·(1+ε)，f 为早 9 晚 20 双峰、凌晨 3:30 低谷；周末 ×0.92 | 形态参照城市污水规律（文献），幅值为经验设定 |
| ② 雨天入流入渗 RDII | Q = 10·ψ·i·A/k，ψ=0.35（规范），k=6/8（截流折减，经验） | 推理公式（GB 50014） |
| ③ 输送延迟 | τ_j = L_j / 0.8 m/s（0.3~3.6h）；厂前 = 各汇水区按 τ_j 延迟叠加（零填充、不回绕） | **严格因果**，有单元测试 |
| ④ 泵站启停 | n_on = clip(⌈n_p·Q/Q_cap + η⌉, 0, n_p)，出流 = n_on·q_unit·U(0.85,1) | 多泵并联分级启停的稳态等效 |
| ⑤ 水质 | 两源按流量加权混合 + 初期冲刷脉冲 + 冲击事件（日概率 5%，COD×1.8~4.0） | 浓度取文献典型值（与 BSM2 同量级） |

**为什么这样设计（要能讲出来）**：

- 开发期用**统计规律生成器**而不是直接上 SWMM：快、可控、可标注（事件标签）、seed 可复现；SWMM 留给"调度验证"环节做物理模型在环——两级模型各有分工。
- **因果性是底线**：`_delay()` 零填充、不回绕，上游信号严格不含未来降雨；预测切分再按提前量剔除跨界标签——我们为此专门修过一个历史 bug（见 3.3），并留了因果性单元测试。

**追问**：

- "模拟器是不是自说自话？"→ 三层防御：① 五机制都有依据（规范/文献/工程假设逐项标注）；② 与真实数据校核量级与形态（旱天形态 vs BSM2；雨天抬升倍数 vs Köln 实测响应）；③ **方法有效性不在模拟数据上声称**——在 Köln 真实数据上独立验证。
- "为什么不用 SWMM 生成全部训练数据？"→ 计算成本与可控性；且 SWMM 参数同样未经泰和率定，换成 SWMM 并不会让数据"更真实"——真实性由公开实测数据背书，模拟只承担"场景完整性"。

### 3.3 特征工程与防泄漏切分（评委最爱抠的细节）

**做法**（`src/models/forecast.py`）：

- 对目标量与每个输入量统一构造：滞后 {1,2,3,4,6,8,12,24} 步 + 一阶差分 + 6 步滚动均值；再加小时（含分钟小数）与星期 = 泰和 62 维特征。
- **发布时刻语义**：t 时刻只用 ≤t 的观测；目标为 t+h 真值；所有模型与基线共用同一对齐，指标可横向比。
- 切分（`src/serving/model.py::training_split`）：按时间 75%/25%；**训练段末端再剔除 h 步**（否则最后几条训练样本的标签落入测试段 = 偷看未来）。

**"我们修过泄漏 bug"的故事（加分项）**：早期版本用 `np.roll` 前移上游序列、让厂前瞬时响应降雨，导致"提前量越长精度反而越高"的伪现象。我们发现后改为零填充因果延迟，并加因果性单元测试（`tests/test_simulation.py::test_plant_inflow_lags_upstream_rain`）——说明我们**知道泄漏长什么样、怎么发现、怎么修复、怎么防回归**。

**追问**：

- "为什么不用交叉验证/随机切分？"→ 时序随机切分会让未来信息漏进训练；我们用时间顺序切分 + 提前量隔离；调参只在训练段内部再切验证段（当前超参是常用起点，**没有在测试集上调参**——在测试集上调参会让指标虚高）。
- "62 维特征会不会过拟合？"→ 训练样本 2 万条（泰和）/7.9 万条（Köln），树模型 + 滞后结构本身有强正则性；我们也做过参数校准网格（`reports/param_sweep.json`）确认当前配置稳健。

### 3.4 模型与基线

**做法**：

- 主模型：LightGBM（400 棵、lr 0.05、63 叶）。理由：① 输入是几十个滞后/差分特征的表格，树模型不需归一化、训练秒级；② 对泵站启停等非线性阈值关系拟合强；③ 原生支持缺测（NaN 走单独分支）——这是后面容错的基础；④ 可用 TreeSHAP 精确分解每次预测。
- 分位数：LightGBM quantile 目标（α=0.1/0.9，各 300 棵）→ P10–P90。
- 基线矩阵（同一数据/切分/语义）：persistence（当前值）、季节朴素（昨日同刻）、MLP(64-32)、LSTM（2 层×64、3h 窗口、5.2 万参数）。

**数字（背）**：

| 数据 | 指标 | +1h | +2h | +3h |
|---|---|---|---|---|
| Köln（真实） | LightGBM NSE | 0.943 | 0.807 | 0.676 |
| Köln | LSTM NSE | 0.922 | 0.787 | 0.637 |
| Köln | persistence NSE | 0.839 | 0.623 | 0.423 |
| 泰和（模拟） | LightGBM NSE | 0.983 | 0.972 | 0.956 |
| 泰和 | persistence NSE | 0.762 | 0.207 | **−0.530** |

训练耗时（Köln +1h）：LightGBM **3.3s** vs LSTM 45.8s（推理 0.20s vs 0.24s）；即"同精度档位下，树模型便宜一个数量级"。

**追问**：

- "为什么树模型赢 LSTM？"→ 样本量与特征结构决定：7.9 万条带强滞后先验的表格特征，树模型占优；LSTM 需更多数据/调参。诚实补充："泰和模拟场景上两者接近（0.983 vs 0.983），我们保留 LSTM 作为对照、选 LightGBM 作为生产主模型，理由是维护成本与推理开销。"
- "为什么不用 Transformer/最新大模型？"→ 任务是单目标短时回归 + 强物理先验（滞后+延迟），文献（如 JECE 2024 系统对比）显示 >1h 后复杂模型优势有限；我们优先可复现、可解释、可部署。数据量上来后可再比。
- "调参了吗？"→ 有参数校准网格与 SWMM 多约束参数寻优记录（`reports/param_sweep.json`、`reports/swmm_constraint_sweep.json`）；预测模型超参保持常用起点、未在测试集上调。

### 3.5 概率预测与不确定性（诚实点，但别只说缺点）

**做法**：LightGBM 分位数回归输出 P10/P50/P90；用 PICP（覆盖率）与 MPIW（区间宽度）评估。

**数字**：Köln PICP 71.5% / 72.1% / 73.8%（名义 80%）；泰和 69.1% / 67.5% / 68.4%——**六组全部欠覆盖**。

**讲法（照读）**："区间代表模型对自身不确定性的估计。当前它偏窄（71.5% vs 名义 80%），我们如实标注'未校准'——上线前会留出校准集做分位数校准（如 conformal/isotonic），并对暴雨场景单独检验覆盖率。给一个假保守的区间比诚实标注更危险。"

**追问**："那你们预警为什么还用 P90 驱动？"→ 演示链路用 P90 是为了展示"分级触发"机制；由于欠覆盖，P90 不是可靠上界，所以预警结论全部限定在模拟场景内、并明确"橙/红无真实正例"。真实上线前要先校准、再定阈值（阈值也需实厂率定）。

### 3.6 极端场景压力测试与跨厂迁移（技术深度的高潮段）

**极端场景**（`src/models/stress_test.py`）：

- 按上海市暴雨强度公式生成芝加哥雨型 2h 设计暴雨（P=5/50/100 年）+ 台风"烟花"（2021）实测降雨回放，驱动模拟器生成 4 个极端场景；用**仅在 2024 汛期基准场景训练**的模型做跨场景测试。
- 结果：P100 未见暴雨 NSE 0.149、峰值低估 −85%（**暴露失败模式**）→ 把 P5/P50 暴雨加入训练增广后，P100 NSE 0.954（**修复**；但 P5/P50 已入训、不再充当独立测试——**诚实标注**）。台风场景 0.917、峰值误差 −2%~−5%。

> 这条"暴露→修复→标注"链是研究方法完整性的最好展示，建议 PPT 用一页专讲。

**真实跨厂**（`src/models/real_transfer.py`）：

- Köln ↔ 丹麦 DHI 两座真实厂互为源/目标；共同输入只有进水+降雨；进水除以发布时刻前 7 天滚动中位数（尺度只取已观测历史，零标签）。
- +2h 零标签迁移：Köln→丹麦 0.511（persistence 0.695、丹麦本地 0.677）；丹麦→Köln 0.708（persistence 0.657、Köln 本地 0.837）。**结论：迁移有效但不如本地训练；新厂上线必须先本地评估/重训。**
- 模拟跨厂负 NSE（+2h 直迁 −3.530）：绝对量纲不可迁移的警示——与真实跨厂的归一化方法不同，**两组数字不能直接比较**（被问到时这是关键澄清点）。

### 3.7 预警与协同调控

**四级预警**（按预测进水占厂设计能力比例；设计能力概化 8000 m³/h）：

| 级别 | 阈值 | 协同调控建议 |
|---|---|---|
| 蓝 | ≥60% | 加强监视 |
| 黄 | ≥80% | 雨前预抽空（预降泵站前池液位） |
| 橙 | ≥95% | 彭越浦总站错峰（上游支线泵站延迟 30~60min 开泵） |
| 红 | ≥110% | 全网限流（上游泵站按能力 70% 限排）+ 调蓄 + 厂内超越预案待命 |

**预警评估**（模拟测试段，P90 驱动）：黄色事件 7 次全部命中（严格口径），误报 6 段；橙/红无真事件——**不能报告这两个等级的召回**。

**SWMM 在环**（`src/swmm/build_inp.py` + `src/control/rolling_opt.py`）：概化 EPA-SWMM 5 模型（6 泵站单元、动力波演算、pyswmm 逐步仿真、每 5min 下发泵指令），P=50a 设计暴雨下四策略对比：

| 策略 | 峰值入流 m³/s | 超阈历时 | 超阈体积 | 前池冒溢体积 |
|---|---|---|---|---|
| 无调控 | 5.80 | 5.6h | 2.09 万 m³ | 19.73 万 m³ |
| 本地液位规则 | 5.80 | 4.9h | 1.76 万 m³ | 20.38 万 m³ |
| 预见性（防冒溢保护） | 5.80 | 4.6h | **1.50 万 m³（−28%）** | 19.73 万 m³（**不增**） |
| 预见性（激进限排） | **4.99** | **2.8h** | **0.22 万 m³（−89%）** | 20.95 万 m³（+6.2%） |

**讲法**："这组实验的价值不在绝对数值（SWMM 是概化参数、未经率定），而在于揭示了一个工程上真实存在的**削峰-冒溢权衡前沿**：要削 89% 就要接受上游多冒 6.2% 的溢流；在'冒溢不增'的约束下稳健策略能削 28%。运行方可以按受纳水体的敏感性选运行点。"

**追问**："这不就是规则引擎？为什么不上 MPC？"→ 是刻意选择规则（可解释、可审计、可现场验证）；物理模型在环已经量化了规则的相对收益与代价；MPC 在展望里，前提是先有实厂率定的模型与数据。

### 3.8 服务化与现场容错（DEMO 15 分 + 实用价值 10 分的支撑）

**做法**：

- FastAPI 演示服务（`src/serving/api.py`）：`/forecast`（严格模式，缺测即 422 拒绝）、`robust=true` 或 `/situation`（容错模式：现在→未来 1~3h→需要关注三段提示）；模型离线训练落盘、请求只加载缓存，不重新训练；响应带 `model_version`（模型文件哈希）。
- 质量控制（`src/serving/quality.py`）：阈值从本厂训练段学习——量程（[0.1%,99.9%] 外扩 50%）、单步跳变（99.9% 分位×3）、恒值 >2h 判卡死（降雨/泵状态除外）；≤30min 缺测向前填充，更长视为离线。
- 缺测增广训练：训练时随机让整个传感器离线（50% 样本）+ 单点缺测（5%）；**超过半数液位计离线 → 自动改用"进水+降雨"简化模型**；进水计整窗口无读数 → 拒绝预测（不编造）。
- 漂移监控（`src/serving/monitor.py`）：预测到期即与实测比对，滚动 1 天 MAE > 1.5×验证期=关注；>2× 且不如当前值基线=失准 → 输出回退当前值。液位计漂移回放：漂移开始 2019-07-02，**11 天后**首次失准报警（慢漂移需累积数天，回退只止损）。
- 谱系（`src/viz/lineage.py`）：183 个源文件/模型/产物的 SHA-256 + 生成顺序 + 软件版本；`--verify` 逐项核验；`.gitattributes` 统一 LF 保证跨平台核验一致。

**数字（Köln +2h，容错实验）**：无扰动 0.808 → 随机缺测 30% 0.789 → 全部液位计离线 **0.773**（常规向前填充只有 0.708）；而**严格模式在这些场景下可服务率为 0**（直接拒绝）。泰和全液位计离线 0.972（常规补齐 −0.939）。→ 一句话："现场传感器一定会坏，我们的模型坏一半还能用，而且明确告诉你它在降级运行。"

**追问**："能接实厂吗？"→ 目前不能：缺生产身份认证、限流、实厂点位映射、时钟同步、控制联锁；接口只是离线回放/演示服务，实厂接入要先旁路评估（`docs/接口说明.md` 与路演问答 Q23 已列清单）。

## 五、评委问答预案（36 问实战答法）

> 原有 23 问的证据版在 `docs/路演专家问答.md`；本节是其超集：更口语、补了行业背景与现场类新题。
> 用法：先按 A/B/D 三类重点过（评委最爱问）；每题先记"一句话答"，展开部分临场发挥。

### A. 数据与合规（Q1–Q6）

**Q1 你们的数据都是哪来的？**
一句话：两类——真实数据（官方骨架、上海实测降雨、国际公开厂网数据集）与模拟数据（泰和全要素时序），逐项登记在 DATA_CATALOG。
展开：泰和厂/网时序是官方骨架+实测降雨驱动的模拟器生成的，报告里所有泰和结果都标"模拟"；方法有效性用 Köln 真实厂网数据验证。
证据：`data/DATA_CATALOG.md`、报告 §2.3 对应表。

**Q2 泰和没有真实时序，你们的结论可信吗？**
一句话：把"可信"拆成两件事——方法有效性靠真实数据（Köln），场景完整性靠模拟（泰和），两者分开声称。
展开：真实性能证据一律以 Köln 为准（NSE 0.943/0.807/0.676）；泰和模拟只验证全链路工程可行性与极端场景敏感性，不代表实厂性能——这是主动写进报告与问答文档的边界。
证据：报告 §2.3 声明、路演问答 Q1/Q3。

**Q3 为什么用德国科隆的数据？和上海有什么关系？**
一句话：它是公开数据里唯一"厂-站-网-雨"结构与赛题完全同构的真实数据集（同一张表：上游管网液位×3+调蓄液位+降雨+厂前进水，3 年 15min 连续）。
展开：国内管网 SCADA 不公开；科隆数据 CC-BY 可复现；用它证明"上游液位+降雨→厂前进水"方法有效，再把同一套方法应用到泰和场景；另做了两座真实厂跨厂迁移验证。
证据：DATA_CATALOG 第 7 项、报告 §4.3。

**Q4 模拟数据怎么保证不是"自说自话"？**
一句话：三层防御——机制有依据、结果与真实数据校核、方法有效性不在模拟上声称。
展开：五机制参数逐项标注"规范取值/文献典型值/经验设定"；模拟结果与 BSM2 形态、Köln 雨天响应量级校核；从不把泰和模拟数字当实厂性能。
证据：`docs/数据说明.md` 五机制表、报告 §3.2。

**Q5 数据许可和知识产权有没有问题？**
一句话：逐项登记、合规优先，不确定的一律不用。
展开：全部来自官方开放平台或开放许可数据集（Köln CC-BY、丹麦 CC-BY-NC 仅非商业、上海水情无条件开放）；授权不清的三方数据明确不取；提交前复核条款。
证据：DATA_CATALOG、路演问答 Q14。

**Q6 有没有拿到国内真实厂网数据？**
一句话：没有可用的——组委会未提供时序，国内管网/厂 SCADA 无公开渠道。
展开：做过渠道矩阵调研（政府开放平台/气象/统计年鉴/科研数据集/人脉），结论是国内无管网级时序公开数据；一条人脉线索经核实属于另一座厂、与泰和无关，无法作为本作品证据，未采用——这是数据方法论里最诚实的一条。
证据：`docs/管网数据调研分析报告.md`、`docs/数据战略_反向解构.md`。

### B. 方法与技术（Q7–Q20）

**Q7 为什么选 LightGBM 而不是深度学习？**
一句话：同精度档位下更便宜、更稳、可解释，且原生支持缺测。
展开：Köln 上 0.943/0.807/0.676 不低于 LSTM（0.922/0.787/0.637），训练 3.3s vs 45.8s；表格滞后特征+非线性阈值（泵启停）是树的强项；NaN 走单独分支是容错基础；TreeSHAP 可精确分解。LSTM/MLP 都跑了对照，不是没做。
证据：报告 §4.5、`reports/deep_forecast.json`。

**Q8 你们的核心创新点是什么？**（背三个，按评委口味挑着讲）
一句话：① 数据方法论——"真实数据验证方法 + 官方骨架/实测降雨模拟场景 + 物理模型在环"，把"无泰和时序"约束转化为可复现路线；② 面向现场的工程化闭环——因果路由严格超前、传感器故障容错、漂移监控回退、谱系核验；③ 削峰-冒溢权衡的量化（SWMM 在环三策略对比）。
（评委偏技术讲①③，偏应用讲②。）

**Q9 特征工程怎么做的？**
一句话：对目标量和每个输入量统一构造 8 个滞后+一阶差分+6 步滚动均值，加时刻与星期，共 62 维。
展开：滞后集 {1,2,3,4,6,8,12,24} 覆盖 5min~2h 多时间尺度；发布时刻语义——t 只用 ≤t 的观测，目标 t+h。
证据：`src/models/forecast.py::feature_rows`。

**Q10 怎么防止数据泄漏？**
一句话：时间顺序切分+训练末端按提前量剔除跨界标签+因果性单元测试；我们还修过一个真实泄漏 bug。
展开：早期 `np.roll` 版本出现"提前量越长精度越高"的伪现象，改为零填充因果延迟并留测试防回归；调参不在测试集上做。
证据：报告 §4.4 注、`tests/test_simulation.py`。

**Q11 NSE 是什么？为什么用它？**
一句话：纳什效率系数——1 完美、0 相当于用均值、负值不如均值；水文领域标准指标。
展开：同时报 MAE/RMSE/MAPE；persistence（当前值）为统一基线——"比当前值好多少"是现场最关心的。
证据：报告 §1.3。

**Q12 P10–P90 区间为什么覆盖率不足？**
一句话：未校准（71.5% vs 名义 80%），如实标注，上线前需单独校准。
展开：分位数回归直接输出、未做后校准；计划留出校准集做 conformal/isotonic + 暴雨场景单独检验；不把 P90 当保守上界。
证据：报告 §4.5(2)、路演问答 Q8。

**Q13 为什么 COD 浓度预测不可靠，负荷却可以？**
一句话：负荷=浓度×流量，流量可预测性强；负荷成绩主要来自流量成分，浓度短板不掩盖。
展开：浓度 +2h NSE −0.047（不可靠）；负荷 0.774~0.801；氨氮负荷 0.914；报告分开评估两种口径。
证据：报告 §4.6、路演问答 Q7/Q17。

**Q14 SHAP 说明了什么？**
一句话：模型输出的相关性分摊、不是因果——Köln 历史进水 37%、管网液位 34%、降雨 15%；雨天降雨升至 28%，与机理方向一致。
展开：TreeSHAP 精确加性（误差 2e-11 L/s）；只解释测试段发布时刻；不声称因果。
证据：报告 §4.9、`reports/shap_summary.json`。

**Q15 极端暴雨下模型会怎样？**
一句话：基准模型在未见过的 P100 设计暴雨上明显低估（NSE 0.149、峰值 −85%）；加入 P5/P50 暴雨增广后 P100 改善到 0.954（P5/P50 已入训、不再独立）。
展开：台风"烟花"实况回放 0.917；设计暴雨未经率定，不宣称防涝收益。
证据：报告 §4.7、`reports/stress_test.json`。

**Q16 换个厂能直接用吗？**
一句话：零标签迁移有效但不如本地训练；新厂上线必须先用本厂数据旁路评估/重训。
展开：两座真实厂互为源/目标：+2h 直迁 0.511/0.708，本地 0.677/0.837；Köln→丹麦方向未超过 persistence；+前 7 天续训可部分弥补；新厂有现成重训命令。
证据：报告 §4.10、路演问答 Q3/Q22。

**Q17 传感器坏了怎么办？**
一句话：质量控制先标缺测；≤30min 向前填充、更长判离线；模型用缺测增广训练；过半液位计离线自动换简化模型；进水计全断则拒绝预测。
展开：Köln +2h 全液位计离线 0.773（常规补齐只有 0.708）；严格模式同场景可服务率 0——容错是净增量。
证据：报告容错节、路演问答 Q19、`reports/robustness.json`。

**Q18 上线后效果变差怎么办？**
一句话：预测到期即与实测比对；滚动 1 天 MAE 超验证期 1.5 倍=关注，超 2 倍且不如当前值=失准→自动回退当前值并提示检查。
展开：液位计漂移回放 11 天后才首次失准报警——慢漂移需累积，回退只止损，根本解是修传感器+重训。
证据：路演问答 Q20、`src/serving/monitor.py`。

**Q19 你们怎么保证可复现？**
一句话：固定依赖版本+一键脚本+随机种子固定+谱系 183 个文件 SHA-256 逐项核验+CI 22 个测试。
展开：现场可演示 `python -m src.viz.lineage --verify`；图表由 `bash deliverables/run_all.sh` 重建；LF 统一保证跨平台核验一致。
证据：`reports/lineage.json`、`操作流程讲解.md`。

**Q20 为什么上游信号能超前？**
一句话：物理输送延迟——污水从管网节点到厂前要走 0.3~3.6 小时（0.8 m/s、0.8~10.5 km），上游液位/流量就是厂前的"预告片"。
展开：模拟器用因果路由（各汇水区按 τ_j 延迟叠加、零填充不回绕）严格保证上游信号不含未来信息——这是"超前感知"的物理基础与因果纪律。
证据：报告 §3.2、`src/simulation/timeseries.py`。

### C. 应用与落地（Q21–Q28）

**Q21 预测出来以后对现场有什么用？**
一句话：`/situation` 一次返回三段——现在（进水占设计能力比例、离线传感器）、未来 1~3h（P10–P90、COD/氨氮负荷）、需要关注（调节池液位/曝气/碳源/传感器核查），只提示不下发指令。
证据：`src/control/advice.py`、路演问答 Q21。

**Q22 四级预警阈值怎么定的？**
一句话：60/80/95/110% × 厂设计能力，对应"加强监视→预抽空→错峰→限流+调蓄"四步"时间换空间"策略；概化设定，实厂需按工艺余量率定。
展开：与 26 泵站能力约束一致；预警链路提前量 120min。
证据：报告 §5.1。

**Q23 SWMM 调度削峰效果？**
一句话：概化 SWMM 在环四策略对比——稳健版削 28% 超阈体积且冒溢不增；激进版削 89% 但上游冒溢 +6.2%；这是一条"削峰-冒溢权衡前沿"。
展开：绝对数值不声称（未经率定），价值在策略间相对比较与方法论闭环。
证据：报告 §5.5、`reports/swmm_control.json`。

**Q24 预警的准确率如何？**
一句话：模拟测试段 7 次黄色事件全部命中、误报 6 段；橙/红没有真事件，不能报告这两个等级的召回。
展开：误报成本分析与实厂率定是上线前提。
证据：`reports/benefit_summary.json`、路演问答 Q10。

**Q25 接实厂还缺什么？**
一句话：已有字段/时间校验、质量控制与降级、滚动监控回退、模型版本与现场提示；还缺生产身份认证、限流、实厂点位映射、时钟同步、控制联锁——需旁路评估后逐步接入。
证据：`docs/接口说明.md`、路演问答 Q23。

**Q26 成本/节能降耗体现在哪？**
一句话：价值=把"事后响应"变"事前预控"——减少雨天工艺冲击的药剂/能耗损失、避免泵组无效空转与溢流风险；模型轻量（训练秒级、推理毫秒级），边缘部署成本低。
（注意：**没有实厂节能数字，不要编**；如实说"这是机制性判断，实厂效益需部署后计量"。）

**Q27 和商用数字孪生平台比，差异在哪？**
一句话：商业平台强在工程集成，我们强在"方法透明+数据诚实+可复现"——完整公开数据来源、指标口径、失败模式与边界，并做了容错与物理模型在环验证；我们覆盖的是它们"感知-预测"前端那一段，互补关系。

**Q28 现场能演示什么？**
一句话：Streamlit 看板四页签（超前感知总览/厂网一张图/暴雨复盘/调控策略对比）+ HTTP 接口现场请求（`/situation` 三段提示）。
（演示脚本见第六章 6.1。）

### D. 局限与边界（Q29–Q33）

**Q29 最大的局限是什么？**
一句话：三条——泰和是模拟场景（非实测）、区间未校准、预警/调度未实厂率定；真实性能证据目前只有 Köln 等公开数据集。
（任何"不足/风险/局限"的变体都用这条。）

**Q30 模拟器为什么不是水动力学模型？**
一句话：开发期选择"公式化概化生成器"（快、可控、可标注），水动力演算交给 SWMM 在调度验证环节做——两级模型分工；接入真实 SCADA 后需重新训练与评估。
证据：报告 §7.2。

**Q31 为什么没有用真实管网水质数据？**
一句话：管网内水质在线监测点在全球都是稀缺品类；我们收录了巴塞罗那管网在线水质等数据集作参照，但泰和没有；水质预测只在模拟场景评估并明确标注。
证据：DATA_CATALOG、报告 §4.6。

**Q32 异常分类 F1=1.0 可信吗？**
一句话：不可当实厂性能——模拟测试段只有 1 次冲击事件且特征显著；它只证明检测链路可行，实厂需多厂真实异常数据重新标定阈值与误报率。
证据：报告 §5.6、`reports/anomaly_metrics.json`。

**Q33 视频/演示里的数据是真实的吗？**
一句话：降雨与 Köln 部分是实测，泰和厂网时序是模拟；视频素材全部可复现，并按"模拟"标注。
证据：报告路演复核区块。

### E. 行业与展望（Q34–Q36）

### 6.3 时间控制与陈述结构

**8 分钟版**（推荐主练）：1 背景 45s + 2 数据方法 90s + 3 模型 90s + 4 结果 90s + 5 闭环应用 90s + 6 边界展望 60s ≈ 7min45s（留 15s 缓冲）。

**5 分钟版**：背景 30s + 方法 60s + 结果 90s + 闭环 90s + 边界 30s。

**15 分钟版**：在 8 分钟版基础上加——SWMM 权衡专页、容错实验专页、跨厂迁移专页、SHAP 专页。

**可砍段落优先级（从先砍到后砍）**：模型细节 → 迁移细节 → SHAP → 数据渠道细节 → SWMM 细节（保住：核心洞察、三个 NSE、演示、边界）。

**彩排要求**：计时练 2 遍；每遍标记超时段落；PPT 页数与段落一一对应（15–20 页）。

### 6.4 不会答三步法

1. **承认**："这一点我们没有做 / 没有数据。"
2. **判断**："基于我们的理解，正确做法应该是……"（给方法论层面的思路，展示专业功底）
3. **收口**："如果给我实厂数据，我会先做 X 再验证 Y。"

（切忌：编数字、装懂、与评委争辩；评委更看重"诚实+有思路"。）

### 6.5 答辩纪律

**必须说的三句话**：
- 数据性质（"这部分是真实数据 / 这部分是模拟场景"）；
- "这条结论的边界是……"；
- "证据在报告第 X 节 / 仓库文件 Y，可以现场核验"。

**不要说的三句话**：
- "我们的模型可以预测任何污水厂"（→ 应该说"换厂需本地重训，迁移实验显示…"）；
- "效果和实测一样"（→ 应该说"模拟场景口径下…，实厂需旁路验证"）；
- "这个数字肯定对"（→ 应该说"在当前口径与切分下是 X，复现脚本与哈希都在"）。
